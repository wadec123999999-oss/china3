# 上海首批实地核验任务包 V1.0

目的：为首批 3–5 单 `Human-checked City Roadbook` 建立足够的、真实的上海现场证据。不是做“上海全攻略”，也不是替客户踩点所有餐厅。

## 第一轮只验证三套可组合单元

| 单元 | 主要客户 | 对应数据库模块 | 本轮要证明什么 |
|---|---|---|---|
| A. 首访城市结构 | 首访、建筑/历史、低体力 | SHM01 河流城市、SHM03 老城、SHM04 博物馆 | 能否在 2 天内形成不赶路的“老城—河流—现代性”理解 |
| B. 雨天/低体力备选 | 雨天、亲子、长者、到达日 | SHM04 博物馆、SHM05 公共空间、SHM13 静安 | 是否能在不硬塞景点的前提下安全替换主线 |
| C. 二访城市观察 | 设计/城市/艺术、复游客 | SHM02 衡复、SHM06 滨水更新、SHM09 苏州河 | 是否能避开“又一套地标”，给出可步行、可退出的城市观察线 |

任何未跑过或未记录过的单元，一律保持 `research_draft`，不作为 Human-checked 路书的关键锚点。

## 每次出门前：统一准备

- [ ] 创建真实 `field_record`，不使用示例文件作证据；
- [ ] 写明日期、天气、星期、出发时间、同行人（如有）和核验角色；
- [ ] 明确今天只验证一个单元，不临时扩张到“顺便全都看”；
- [ ] 带充电、备用网络、简单雨具；遵守场馆、居民区、宗教场所的拍摄规则；
- [ ] 不拍可识别的儿童、私宅内部、宗教活动或工作人员工作细节，除非获明确许可；
- [ ] 发现 P0/P1 情况时先记录事实、停止把它当候选推荐，不凭经验修补。

## 每个锚点必须记录的 12 项

1. 何时、从哪里抵达；
2. 与前一锚点的真实迁移方式与体感负担（不写伪精确分钟数）；
3. 路面、台阶、过街、遮阴、座位、厕所、补水和撤回点；
4. 高温、下雨、强风、拥挤时的变化；
5. 开放/预约/安检/携包/拍摄等规则的**来源**与日期；
6. 英语标识、支付、网络、问路会在哪一步摩擦；
7. 对儿童、行动限制、疲劳或时差旅客的真实难点；
8. 周边是否有“不花钱也能恢复节奏”的替代空间；
9. 叙事是否成立：客户在此能看懂什么，而非只是拍什么；
10. 哪个时间段最不适合作为推荐；
11. 客户实际应自行确认/预订的事项；
12. 这条证据何时过期、下次应何时复核。

## A 包：首访城市结构（建议两次走）

### A1：老城 + 城市叙事

**任务问题：** 如何让首访客理解“商业、礼仪和老城形态仍在巨型城市中共存”，而不落入主题公园式打卡？

- [ ] 从一个现实的客户住宿大区出发，记录抵达老城的摩擦而非只从入口开始；
- [ ] 走一段能够观察日常商业、公共礼仪和街巷尺度的公开区域；
- [ ] 记录拥挤、排队、施工、推车/轮椅/婴儿车、雨天积水或闷热风险；
- [ ] 检查任何宗教或历史场所的摄影、安静、预约和进入规则来源；
- [ ] 找到一处不依赖消费的低体力撤回点；
- [ ] 写出“该删掉什么”：例如不能同日叠加过多老城、博物馆、河岸和晚间远距离移动。

### A2：河流城市 + 夜间回撤

**任务问题：** 如何把外滩—陆家嘴从“自拍背景”变成殖民贸易、河流、金融与现代城市尺度的理解？

- [ ] 分别在日间与天黑后观察人流、风、遮蔽、拍摄与回程难度；
- [ ] 记录横跨/眺望的实际决策点，但不承诺特定渡轮/路线必然运行；
- [ ] 标记容易产生“拍完却不知道下一步去哪”的位置与恢复节奏策略；
- [ ] 检查夜间公共交通、步行安全感和雨天撤回逻辑的官方来源入口；
- [ ] 确定一条不需要夜生活消费的夜间收束线。

## B 包：雨天/低体力备选

**任务问题：** 当客户在到达日、炎热雨天、孩子疲劳或长者同行时，怎样不把室内场馆堆成另一种赶路？

- [ ] 选择一个馆/公共空间作为主锚点，核验当前预约、开放、安检和携包规则的官方入口；
- [ ] 从站点/落客点走到入口，记录雨伞、雨天积水、门厅排队与休息座位；
- [ ] 找到同一小区域内的 `Plan B`，而不是跨城替换；
- [ ] 记录儿童厕所、母婴、轮椅等信息的缺口：不确定就写“需客户自行向场馆确认”；
- [ ] 测试一句英文问题能否解决关键摩擦；不能就把中文关键词/截图需求写入摩擦卡；
- [ ] 给此单元设一个“最多停留”提示，避免因下雨被困成全天室内疲劳。

## C 包：二访城市观察

**任务问题：** 如何让设计/城市兴趣客在衡复、滨水或苏州河看到“城市如何被再利用”，而不是走一套商业街？

- [ ] 选一条连续、公开、无需强制消费的步行段；
- [ ] 分开记录公共空间、居民边界、商业空间和办公区，避免把住宅生活当观光内容；
- [ ] 记录路面连续性、施工、树荫、长椅、洗手间、雨天和夜间照明；
- [ ] 对任何展览/建筑内部只记录公开、可查的进入规则；不许诺活动/私宅/工作室访问；
- [ ] 写出一段“为什么这条线适合二访”的城市问题，以及何种客户不应该走；
- [ ] 找一个半途退出点，验证从此处回酒店/核心交通的逻辑。

## 出门后 30 分钟内完成的回写

- [ ] 写入 `field_record` schema：证据、发现、客户影响、输出规则、P 级别、下次复查日期；
- [ ] 更新对应城市模块的 `field_status`，而不是只把照片放相册；
- [ ] 若动态项未查到可靠来源，设为 `needs_recheck`，不以“现场看起来没问题”代替；
- [ ] 记录至少一个应删除或降级的推荐，防止数据库只会加内容；
- [ ] 将客户语言、英文字段、时间/体力表达写入摩擦库；
- [ ] 对 P0/P1 发起人工复核任务，不等待有客户下单才处理。

## 首轮完成定义

完成不是“走了三条路线”。只有同时具备以下证据，上海才可开始小范围出售 Human-checked 路书：

- A、B、C 每个单元至少 1 条真实、非示例 `field_record`；
- 每条主线至少 1 个有效退出/备选规则；
- 关键动态信息都有可复查来源入口与复核日期；
- 没有把太极、工作室、餐饮或其他候选资源误写成已放行服务；
- 能用一份真实客户 brief 测试并生成符合该客户限制的样稿；
- 发布人完成质量系统中的 P0/P1 检查并留痕。
