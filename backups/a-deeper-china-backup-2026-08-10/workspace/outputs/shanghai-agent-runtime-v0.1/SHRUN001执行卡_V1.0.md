## 只核验这一条问题

> 一个第一次来上海的英语游客，能否在不依赖中文帮助的情况下，完成“人民广场—上海博物馆/周边”的半日文化起步，并知道雨天、排队、疲劳和离场时该怎么调整？

不要顺便测试外滩、武康路、太极或其他城市模块；它们分别属于 `SHRUN002`、`SHRUN003` 和 `SHRUN006`。

## 建议观察顺序

1. 从实际游客会使用的入口开始，记录从入口到第一个清晰方向指示的时间。
2. 记录安检、预约/核验、寄存、卫生间、饮水、座位和出口位置；不拍摄个人证件或陌生人正脸。
3. 记录英语信息出现在哪里、是否能支持下一步决定；不要把“有英文页面”写成“现场全程英语可用”。
4. 以普通游客节奏完成人民广场公共空间与博物馆周边，不追求最快速度。
5. 记录实际用时、迷失/回头、排队、施工、拥挤、休息和儿童/老人可能遇到的摩擦。
6. 设计一个雨天或高温删减版本：明确删掉什么、保留什么、从哪里退出。
7. 完成后写出一条“什么时候不该推荐这条路线”的反例。

## 必须留下的证据

至少两项，且能被另一位审核人追溯：

- 一条不含敏感个人信息的路线记录或地图截图；
- 入口/指示/规则/休息条件的现场照片或文字记录；
- 如涉及当日开放或预约，保存官方页面截图并注明检查时间；
- 实际计时记录；
- 任何工作人员答复，记录地点、问题、时间和原意，不记录不必要的个人信息。

## 通过门槛

只有同时满足以下条件，才可把 `SHRUN001` 填为 `pass`：

- 实际入口、出口、耗时和至少两个摩擦点有可追溯证据；
- 预约、开放、英语信息等动态内容注明检查时间；
- 能给出可执行的雨天/高温删减方案；
- 没有重大安全误解、隐私越界或“英文全程无障碍”的过度结论；
- 另一位审核人能根据记录复算你的判断。

若有条件成立但仍缺一项，填 `conditional_pass`；没有真实记录时只能填 `incomplete`，不能用网络资料代替现场记录。


然后执行：

```bash
node outputs/shanghai-agent-runtime-v0.1/bin/validate-field-record.mjs outputs/shanghai-agent-runtime-v0.1/field-records/SHRUN001.json
node outputs/shanghai-agent-runtime-v0.1/bin/field-progress.mjs
```

验证通过不等于自动收费放行；还要由人工审核人确认路线改写和客户适配范围。
