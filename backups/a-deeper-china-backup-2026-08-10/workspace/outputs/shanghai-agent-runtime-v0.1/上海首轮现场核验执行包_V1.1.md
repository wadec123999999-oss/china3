# 上海首轮现场核验执行包 V1.1

用途：把上海数据库从“研究内容”推进到“可复核的现场证据”。本文件是执行包，不是客户路书，也不把网络资料或个人印象当成核验结果。

## 使用顺序

建议按以下顺序执行：

1. `SHRUN001` 人民广场—上海博物馆/周边：首访与雨天基础框架；
2. `SHRUN002` 外滩—过江—浦东：上海总览线；
3. `SHRUN003` 衡复—武康—公园：建筑慢行线；
4. `SHRUN004` 杨浦滨江或西岸：二访城市观察线；
5. `SHRUN005` 外国游客可用性测试：验证英文路书是否真的能被使用；
6. `SHRUN006` 英文太极体验：单独的供应商和安全放行，不与城市路书自动绑定。

每次只执行一个 `run_id`。如果某条路线在现场不成立，记录为 `conditional_pass`、`fail` 或 `incomplete`，不要为了让进度变绿而改写事实。

## 统一记录要求

每条记录必须包含：

- 真实核验日期、开始时间、核验人；
- 当天天气、体感、人流和是否周末/节假日；
- 实际入口、出口、移动顺序和总耗时；
- 至少两个身体或操作摩擦点；
- 至少两个可追溯证据；
- 一条低体力或雨天删减方案；
- 一条“不该推荐这条路线”的反例；
- 对数据库、英文路书需要修改的具体句子。

现场拍摄不得包含陌生人的可识别正脸、身份证件、电话号码、支付信息或私人住宅内部。

## 六项任务卡

### SHRUN001｜人民广场—上海博物馆/周边

**核心问题**：第一次来上海的英语游客，能否在不依赖中文帮助的情况下完成一个半日文化起步，并处理预约、排队、雨天和疲劳？

**必须观察**：入口到第一个清晰指示的时间；预约/安检/寄存；英语信息是否支持下一步决定；厕所、饮水、座位；真实耗时；雨天或高温退出点。

**最低通过条件**：入口、出口、耗时和至少两个摩擦点有证据；动态信息注明检查时间；能写出可执行的删减版；没有把“有英文页面”夸大为“全程英语无障碍”。

### SHRUN002｜外滩—过江—浦东

**核心问题**：游客是否能通过一次清晰的两岸转换理解上海，而不被排队、过江方式、拥挤和夜间返程破坏体验？

**必须观察**：实际起点与结束点；过江方式和等待；人流、热暴露、雨天替代；浦东侧的安全退出和返程；蓝调/夜间时段是否仍适合慢节奏游客；是否需要删掉观景台或商场绕行。

**最低通过条件**：记录一条可复算的两岸移动链；记录等待和返程风险；给出不跨江版本；不承诺特定日落、灯光或拍摄位置。

### SHRUN003｜衡复—武康—公园

**核心问题**：建筑爱好者能否通过一条连续街区理解尺度、树荫、入口、再利用和居住边界，而不是变成打卡路线？

**必须观察**：连续步行的真实分钟数；树荫、座位、厕所和道路过街；施工与拥挤；住宅隐私和拍摄边界；低体力回撤点；雨天是否仍有可解释的室内替代。

**最低通过条件**：至少一条连续公共街段有轨迹或计时；明确停止点和回撤点；记录一条不进入住宅、不追逐居民生活的拍摄规则；若路段不连续，必须改写路线而不是保留地图上的直线。

### SHRUN004｜杨浦滨江或西岸

**核心问题**：滨水工业遗产/公共空间是否能在真实步行成本下讲清“工作如何变成公共空间”，而不是一条很长的景观散步？

**必须观察**：实际起终点和连续性；遮荫、厕所、座位、饮水；桥梁/施工/封闭段；白天与傍晚照明；节目和开放状态；从哪里开始失去叙事价值，应在哪里停止。

**最低通过条件**：留下“保留哪一段、删掉哪一段”的明确决定；记录完整回撤方案；不能用地图距离推断体力成本；若节目或场馆是动态条件，必须标注检查日期。

### SHRUN005｜外国游客路书可用性测试

**核心问题**：一名非中文母语者能否只依靠英文路书完成路线，并在关键节点理解“继续、停止、删减或求助”？

**测试方法**：给测试者一份不含内部 ID、不过度解释的英文路书；不要在途中主动提示；记录迷路、误解、找不到入口、支付/导航障碍、疲劳和对 stop rule 的理解。

**必须输出**：逐段完成率；每个误解的原句；需要改写的标题、方向或边界句；测试者对“为什么删掉某个热门点”的理解；对“这不是预订或导游承诺”的理解。

**最低通过条件**：关键入口、退出点和删减逻辑不依赖口头补充；所有重大误解都有修订动作；不能用“测试者说还不错”代替逐项记录。

### SHRUN006｜英文太极体验

**核心问题**：是否存在一个真实、可验证、适合外国游客的英文太极产品？

**七项放行门**：

1. `english_trial`：实际试教，不以自述英语能力替代；
2. `credentials`：师承、教学经历和可公开介绍资历；
3. `venue`：固定场地和雨天备用场地；
4. `delivery`：每次人数、时长、内容和价格；
5. `filming`：是否同意拍摄及海外宣传，范围需书面确认；
6. `transaction`：预约、付款、取消和改期规则；
7. `safety`：热身、动作边界、保险/责任、伤病处理和不适退出。

**最低通过条件**：七项全部为 `pass`，并有对应证据；任何一项缺失只能是 `conditional_pass` 或 `incomplete`，不得报价、收款或在路书中写成已安排体验。

## 记录与验证命令

先创建空白记录，不覆盖已有文件：

```bash
node outputs/shanghai-agent-runtime-v0.1/bin/new-field-record.mjs SHRUN001
```

填写真实记录后验证：

```bash
node outputs/shanghai-agent-runtime-v0.1/bin/validate-field-record.mjs \
  outputs/shanghai-agent-runtime-v0.1/field-records/SHRUN001.json

node outputs/shanghai-agent-runtime-v0.1/bin/field-progress.mjs
```

当前没有任何正式现场记录，因此本执行包不会改变上海的 `not_started` 状态，也不会改变收费或体验放行边界。
