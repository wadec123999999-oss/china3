# A Deeper China｜城市知识库与主动互动统一契约 V1.0

更新：2026-08-09

## 结论

目前有 **13 个城市数据库**，组织成 **10 个可选择的路线产品单元**。每个产品单元都拥有：

- 城市数据库来源引用；
- 城市定位与“不适合什么”；
- 至少 5 个高影响追问；
- 至少 3 个潜在需求假设及确认问题；
- 城市取舍、停留时间和删除规则；
- 人工复核触发条件；
- 输出时必须强调的重点。

知识库不是“景点目录”。它采用 task-first 结构：先判断游客要解决的旅行问题，再选择城市、路线和点位。

## 运行顺序

```text
游客原话
  ↓
显性需求 + 可确认的潜在需求假设
  ↓
城市/城市组路由
  ↓
最多两个会改变路线的主动追问
  ↓
城市取舍规则、低体力/雨天分支、删除建议
  ↓
研究型路书草稿
  ↓
日期化人工复核
  ↓
可发布路书（只有证据满足放行条件时）
```

## 统一字段

| 字段 | 用途 |
|---|---|
| `identity.what_it_is` | 说明这个城市真正解决的旅行问题 |
| `identity.not_for` | 主动阻止错误期待和不合适的加点 |
| `selection_rules` | 判断保留、删除、拆分和最低停留时间 |
| `latent_need_rules` | 把未说清的动机写成“待确认假设”，不能当作事实 |
| `follow_up_questions` | 按优先级主动追问，最多取两个 |
| `human_review_triggers` | 触发人工复核、研究-only 或拒绝承诺 |
| `output_emphasis` | 要求路书输出重点，而不是景点堆叠 |

## 城市覆盖

上海；杭州；苏州；北京；成都；重庆；广州；深圳；桂林—阳朔；泉州—德化；景德镇；武当山；景迈茶山。

产品单元为：上海、杭州—苏州、北京、成都—重庆、广州—深圳、桂林—阳朔、泉州—德化、景德镇、武当山、景迈茶山。

## 当前边界

- `field_verified_count = 0`：当前数据库仍是研究基础，不等于所有路线已实地核验。
- 动态开放、预约、交通、天气、支付、台阶、拍摄和社区规则必须在交付前重新检查。
- 不承诺私人住宅、农户、工作室、宗教仪式、师傅/老师、企业/工厂、代订或代收款。
- 武当山和景迈茶山保持 `research_led`；只有公共访问、道路、天气和人工记录齐备后，才能进入更强的商业放行状态。

## 检索实现

`retrieval-index-v1.json` 定义四层检索：全局路由、城市决策、城市细节和全局边界。`src/retrieval.mjs` 会先生成检索计划，再按 `destination_slug` 和内容类型建立候选集。

```bash
npm run plan-retrieval -- "First visit to Beijing for history and the Great Wall, three nights."
```

单城市问题只打开该城市的详细记录；比较问题只打开被比较的城市；没有城市的问题先检索小型产品层，不直接加载所有点位。
