# A Deeper China｜独立站接口接入说明 V1.2

本文对应当前公开路书 JSON 合同。网站暂不需要立即改版；接入时应以结构化 `public_roadbook` 为准，不要从 Markdown 标题猜字段。

## 网站可以读取的公开字段

| 字段 | 用途 | 是否可直接展示 |
|---|---|---|
| `city` | 城市名称 | 是 |
| `route_thesis` | 本次路线主旨 | 是 |
| `why_this_route` | 选择理由 | 是 |
| `trip_context` | 已确认日期、人数、节奏、住宿区域、语言 | 是，需脱敏 |
| `decision_brief` | 客户明确需求和推断需求 | 是，但推断内容应显示为“待确认” |
| `delivery_status` | 当前交付状态 | 必须显示 |
| `route_controls` | 每天一个问题、停止规则、恢复时间 | 是 |
| `days[].modules[]` | 每日路线模块和执行卡 | 是 |
| `checks_before_delivery` | 发送前核验清单 | 可显示为“仍需确认” |
| `delivery_boundary` | 不构成预订或供应商承诺 | 必须保留 |

## `delivery_status` 的前端表现

```json
{
  "public_state": "draft_for_human_review",
  "current_checks_required": true,
  "human_review_required": true,
  "booking_created": false,
  "explanation": "Current checks and human review are required before client delivery."
}
```

建议显示为：

- `research_draft`：Research draft
- `draft_for_human_review`：Human review in progress
- `human_checked_ready`：Human-checked roadbook

即使是 `human_checked_ready`，也不能显示“已预订”“保证开放”或“供应商已确认”，因为 `booking_created` 永远为 `false`。

## 网站不得读取或展示的字段

不得把下列字段从内部运行时或数据库发送到浏览器：

- 内部模块 ID、点位 ID、来源 ID；
- `score`、`confidence`、内部排序和 source pack；
- 供应商 ID、候选供应商、联系方式和准入状态；
- 原始聊天全文、审核人隐私信息和内部 release gate 细节；
- 未脱敏的现场记录、居民信息、私密访问信息。

公开契约校验器会拒绝内部键：

```js
import { validatePublicRoadbook } from './src/public-roadbook-contract.mjs';

const result = validatePublicRoadbook(publicRoadbook);
if (!result.valid) throw new Error(result.errors.join('; '));
```

## 推荐页面流程

1. 客户输入原话；
2. `/api/route-direction` 返回路线方向和一个最高优先级追问；
3. `/api/dispatch-runtime` 生成研究草稿和公开 JSON；
4. 显示 `delivery_status`、客户简报、路线主旨和每日执行卡；
5. 客户确认日期、人数、节奏和限制后，生成 human-review packet；
6. 人工核验 current-source / field-run 记录；
7. 只有 release gate 返回 `human_checked_ready`，页面才可显示 Human-checked roadbook；
8. 预订、支付、交通、住宿和第三方体验仍然是独立流程，不由本数据库自动完成。

## 免费预览与付费升级

在完整 intake 尚未进入付费交付前，网站可以调用：

```text
POST /api/route-preview
```

它只返回 `route_preview` 产品的 fit-check：路线主旨、客户已表达的需求、最多两个候选模块、一个待确认问题和升级到 `deep_roadbook` 的理由。

预览必须满足以下边界：

- `status` 必须是 `preview_only`；
- `commercial.payment_allowed` 和 `commercial.quote_allowed` 必须为 `false`；
- 不得包含 `days`、`markdown`、内部模块 ID、点位 ID、来源或供应商字段；
- 不得显示为完整行程、人工核验完成、预订或可售体验；
- 返回前运行 `validate-route-preview.mjs`，失败则不发送给浏览器。

付费升级不是自动扣款。用户表达升级意愿后，网站应重新提交完整客户 intake，由后端返回 `deep_roadbook` 的人工范围报价状态；第三方体验仍走独立审核流程。

## 不要把 Markdown 当作接口合同

Markdown 用于客户阅读和 PDF 渲染；网站组件必须使用 `public-roadbook.schema.json` 和 `delivery_status`。Markdown 可能增加编辑性文字，但结构化字段才是稳定接口。

## 当前版本边界

- 当前 13 个城市均为研究数据库和受控路书运行时；
- 现场核验通过数仍可能为 0；
- 网站接入前，必须重新运行公开样本审计和 `npm run audit:all`；
- 本文不代表任何城市已经预批准或可自动销售。
