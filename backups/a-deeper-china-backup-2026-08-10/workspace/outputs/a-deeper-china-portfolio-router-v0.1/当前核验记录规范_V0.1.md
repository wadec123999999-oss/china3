# 当前核验记录规范 V0.1

客户路书不能因为有人输入了一个来源 ID，就被标成已核验。每一条用于放行的记录必须含有：

- `kind`：`current_source`（当前来源）、`dynamic_check`（现场/动态任务）或 `field_run`（已完成的现场实走/电话核验）
- `id`：来源或动态任务的既有 ID
- `applies_to_travel_start`：必须等于该客户行程首日
- `checked_by`、`checked_at`：谁在何时查的
- `evidence_url`：官方页面、截图存储地址或通话记录地址
- `finding`：对客户日期有效的具体结论；不能写“已确认”这类空话

`createRoadbookBrief()` 只从通过验证的记录中抽取 `current_source_ids` 与 `completed_check_ids`。即使所有闸门通过，它也只会输出 `eligible_for_human_review_signature`；之后仍须由人工审核记录签字，才能称为 **Human-checked digital roadbook**。

`field_run` 只有在 `result: pass`、包含具体 `module_ids`、至少一条 HTTPS 证据、真实核验人、核验时间和客户旅行首日后，才会把对应模块送入 release gate。`conditional_pass`、`fail` 和 `incomplete` 都不能放行。

## 日期化任务模板

`createCurrentSourceTasks()` 会根据城市、模块和旅行日期，从日期化来源刷新文件生成空白任务。任务只携带“需要核验的 claim”和来源页，不携带任何假定的检查结果。

每个任务必须由人工填写：

- `checked_by`
- `checked_at`
- `evidence_url`
- `finding`

任务的 `applies_to_travel_start` 必须等于客户行程首日。没有这些字段，任务不能进入 `current_source_ids` 或 `completed_check_ids`。
