# A Deeper China｜社区平台采集卡与去广告流程 V0.1

适用：小红书、马蜂窝、穷游、微博、抖音、B站、点评、携程、Reddit、YouTube、TikTok。目的不是“搜到更多推荐”，而是找出客户会问、通用 AI 容易漏、且值得在地复核的决策问题。

## 一条内容的去留

| 结论 | 条件 | 数据库动作 |
|---|---|---|
| 丢弃 | 无具体地点/时间/行为；纯景观赞美；明显复制；只导向商家下单 | 不建记录；只可留检索关键词 |
| 研究线索 | 有具体摩擦、反例、取舍或客户语言，但作者/利益关系无法充分确认 | 建 `source-record`，`review_status=community_signal_only`，`source_use=lead_only` |
| 待交叉验证 | 可辨认的独立一手经历，且与另一独立来源提出同一个长期问题 | 建记录和交叉证据；仍不得生成动态运营答案 |
| 可用于语境 | 非动态的文化/城市背景，已由官方、学术或现场资料确认 | 引用时标注来源与边界 |

## 采集卡：每次只回答一个问题

```text
城市/模块：上海 / SHM__
客户原话或搜索词："I have one free afternoon; do I need a food tour?"
平台与链接：小红书 / 马蜂窝 / 穷游 / Reddit …
抓取日与内容发布日期：
观察到的具体信号：只写作者实际提出的困惑、取舍或失败；不写结论。
潜在客户需求（假设）：例如“怕踩雷”或“行动力有限”。必须附一个确认问题。
广告信号：无 / 佣金 / 免费招待 / 商家本人 / 价格引流 / 关系不明
独立性：可辨认一手 / 一手不清 / 搬运 / 匿名
允许绑定模块：最多 3 个；不许泛化成整座城市的证据。
下一步：官方页、地图、现场走访、电话或另一位独立作者中的哪一种？
结论：丢弃 / lead_only / 待交叉验证
```

## 平台的“高价值问题”，而不是“高赞答案”

| 平台 | 优先抓什么 | 必须避开什么 |
|---|---|---|
| 小红书 | 实际动线、排队、带老人/儿童/行李、季节体感、中文检索词 | 探店榜单、团购链接、单店“必吃”、滤镜式种草 |
| 马蜂窝 / 穷游 | 跨城节奏、失败复盘、行程取舍、旧攻略里仍可复核的问题 | 旧票价、旧车次、复制行程和论坛中的“据说” |
| 点评 / 携程 | 一类餐饮或住宿的近期摩擦词、语言/支付需求 | 排名、星级、商家回复、折扣和“最好”结论 |
| 视频平台 | 空间尺度、行动成本、游客期待和误解来源 | 被剪掉的排队/预约/许可限制、接待换取的体验 |
| 海外社区 | 外国护照、支付、SIM、语言、独行安全感、文化预期 | 把一人经历扩成规则，或接受私信中的商家转介 |

## 三项反广告检查

1. **利益关系**：作者是否销售、带货、收佣金、接受招待或在评论区导流？是则锁为 `lead_only`。
2. **可证伪性**：是否给出具体的日期、地点、行动、失败原因？没有则不入库。
3. **独立重复**：相同说法是否只存在于互相引用的内容？是则视为传播，不算交叉证据。

## 给智能体的输出边界

社区内容只可影响三件事：追问什么、避开什么误解、优先核验什么。它不能单独输出任何场馆开放、预约方式、价格、交通、供应方、食品安全、私人进入、拍摄许可或“本地最正宗”的结论。
