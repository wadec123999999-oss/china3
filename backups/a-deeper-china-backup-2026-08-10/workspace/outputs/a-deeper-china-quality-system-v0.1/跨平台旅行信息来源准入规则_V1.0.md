# A Deeper China｜跨平台旅行信息来源准入规则 V1.0

## 核心结论

小红书、马蜂窝、穷游、Reddit、YouTube 等都可以贡献高质量信息；但它们在数据库中默认是**线索来源**，不是结论来源。平台不决定可靠性，主张本身的独立性、时间、利益关系、交叉证据和现场记录才决定它能进入哪一层。

## 四层使用权

| 来源状态 | 能做什么 | 不能做什么 |
|---|---|---|
| `lead_only` | 发现候选点、关键词、摩擦、季节问题、潜在合作方 | 直接进入游客答案 |
| `corroborate_before_database` | 进入研究队列，等待独立来源/官方/现场交叉验证 | 作为动态事实或推荐 |
| `context_with_citation` | 支持长期语境、旅客感受或历史解释 | 支持开放、价格、可订、体验安全承诺 |
| `eligible_for_human_checked` | 仅在有真实 field record 后，支持客户相关路书 | 永久有效；动态项仍须按日期复查 |

## 平台应该怎么用

| 平台 | 高价值信号 | 高风险噪音 | 默认动作 |
|---|---|---|---|
| 小红书 | 本地空间变化、季节体感、拍摄/排队摩擦、中文关键词 | 探店软广、佣金/团购、滤镜化“必去”、复制笔记 | 取线索，查商业关系，找独立交叉证据 |
| 马蜂窝 / 穷游 | 长行程结构、旧攻略中可复查的路线假设、评论讨论 | 过期交通/票务、商家植入、作者多年未更新 | 只保留不随时间变的决策问题 |
| 携程 / 大众点评 | 近期营业/排队/语言摩擦线索 | 排名、刷评、商家回应、价格/过敏承诺 | 不能用作“最好/安全/必订”结论 |
| Reddit | 海外客真实支付、网络、语言、路线困惑 | 个别经历泛化、删帖、主观偏见 | 回写常见问题；不把单帖当事实 |
| YouTube / TikTok / 抖音 / B站 | 空间感、创作意图、画面与旅客期待 | 剪辑掉了限制、广告/接待、许可不明 | 当视觉参考，不当运营说明 |
| 官方 / 场馆直接信息 | 规则、开放、预约、公共政策、基础遗产事实 | 更新滞后、营销式表述 | 动态项目仍记录日期和复核人 |

## 三个广告识别问题

1. 作者是否从预订、团购、佣金、免费招待、课程、带货或自身商家身份获益？
2. 内容是否使用无法被复查的绝对词：`最正宗`、`内部渠道`、`保证`、`本地人不告诉你`、`全网第一`？
3. 该主张是否只在同一批互相转发的帖子中出现？

任一为“是”，记录 `commercial_signal` 或 `repost_or_compilation`，最多作线索。

### 机器可执行的硬规则

以下内容在未形成独立的现场核验记录前，`source_use` 必须为 `lead_only`：有佣金/赞助/免费招待信号、商家或供应方自述、搬运/合集、作者无法辨认的内容。即使它提及临时开放、课程、价格或交通，也**不会**自动变成 `requires_current_check` 的发布证据；应由独立官方信息或人工电话/现场复核另建一条动态核验记录。

## 动态事实永远不自动升级

以下项目即使来自官方，也必须在客户相关日期重查：开放/预约、交通、天气、水位、施工、票价、排队、餐厅营业、步道、活动、课程、供应方可用性。

## 进入数据库前的最小记录

每条候选信息都要写：来源平台、链接、发布时间/抓取时间、城市、具体主张、商业关系、作者独立性、至少一个交叉证据、当前状态、下次复查日。使用 `source-record.schema.json` 与 `scoreSource()`，而不是只收藏链接。
