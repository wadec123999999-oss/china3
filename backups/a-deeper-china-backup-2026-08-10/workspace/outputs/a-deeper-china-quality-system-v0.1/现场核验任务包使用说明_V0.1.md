# 现场核验任务包使用说明 V0.1

## 生成空白记录

例如生成上海人民广场博物馆路线的手机填写模板：

```bash
node field-record-template.mjs Shanghai SH-FIELD-001
```

如果已经确定真实核验日期，可以传入第三个参数：

```bash
node field-record-template.mjs Shanghai SH-FIELD-001 2026-08-03
```

输出默认是 `incomplete`。填写完成后，必须保留：

- 实际核验日期和核验人；
- 这条记录适用的客户旅行首日 `applies_to_travel_start`；
- 天气、人流、入口、退出和体力信息；
- 至少两条可追溯证据；
- 对客户日期有效的具体结论；
- 需要修改数据库或路书的地方。

## 转换为路书证据

当记录已经真实完成并且结果为 `pass` 时，可以转换成 release gate 使用的证据：

```bash
node bin-field-evidence.mjs path/to/field-record.json --travel-start 2026-09-10
```

转换器不会接受 `conditional_pass`、`fail`、`incomplete`、本地路径证据或缺少客户旅行首日的记录。

## 放行边界

只有真实记录才能把结果改为 `pass` 或 `conditional_pass`。如果记录依赖私密空间、未获同意的拍摄、未经确认的供应商、未验证的安全条件或未来日期，必须保持 `incomplete` 或 `fail`。

模板中的 `cannot_promote_to` 是对客边界，不是待办清单；它提醒复核员哪些说法即使路线走通也不能写进销售页。
